# Genesis Mesh Did Not Start With Genesis Mesh

Genesis Mesh may look like a response to the current rise of AI agents, sovereign AI, and autonomous systems.

It isn’t.

**My work has a documented pattern of AI experimentation going back to 2016, covering distributed AI infrastructure, assistants and neural networks. By 2023, that work had moved into original multi-agent architecture. Genesis Mesh grew from the trust and authority problems that appeared once those systems became distributed.**

Genesis Mesh today: [genesismesh.org](https://genesismesh.org) · [GitHub](https://github.com/GenesisMeshLabs)

Years before Genesis Mesh had a name, I built a Proof of Concept called the **Intelligent Agents Network**.

The goal was simple: explore what happens when intelligent agents stop being isolated assistants and start becoming parts of a larger system.

The PoC explored a modular architecture where specialized agents could communicate with each other, integrate with external systems, interact through voice, text and visual interfaces, and trigger automated infrastructure workflows. Security was also part of the architecture, with validation and proxies protecting critical functions. ([thaersaidi.com](https://thaersaidi.com))

You can still see the original PoC here:

[Intelligent Agents Network PoC](https://www.thaersaidi.com/poc.html)

**The question that came next**

Once agents can communicate and execute actions, a much harder problem appears:

**Why should one agent trust another?**

And then more questions follow.

Who gave the agent permission?

What exactly is it allowed to do?

Can that authority be delegated?

Can it cross organizational boundaries?

Can it be revoked immediately?

Can we prove afterwards exactly what happened?

Many agent frameworks focus mainly on orchestration.

Genesis Mesh is about solving **authority**.

**From agent communication to agent trust**

The original PoC already focused on communication between agents, external integrations, modular architecture, automation, and protected critical functions. ([thaersaidi.com](https://thaersaidi.com))

Genesis Mesh takes those ideas further.

Instead of simply:

**Agent → Agent**

the model becomes:

**Human → Authority → Delegation → Agent → Capability → Execution**

Every participant can have its own identity.

Every capability can have a defined scope.

Every delegation can be verified.

Every action can be audited.

And authority can be revoked without having to shut down the entire network.

This becomes especially important when the agents do not belong to the same organization.

**The cloud should not own the trust model**

This is where sovereign architecture becomes important.

Imagine an agent running locally.

Another agent is operating in a European cloud.

A third belongs to another organization.

A fourth uses a commercial AI provider.

They may need to work together, but that does not mean they should all surrender control to one cloud provider, one identity provider, or one AI company.

Genesis Mesh is built around a different idea:

**Cooperation should not require centralized ownership.**

AWS can provide compute.

Azure can provide compute.

A sovereign cloud can provide compute.

A local NVIDIA machine can provide compute.

An AI provider can provide intelligence.

But none of them should automatically become the ultimate authority over the entire system.

**This changes the meaning of sovereignty**

Sovereignty is often described as where the server is located.

I think that definition is incomplete.

A workload can physically run in Sweden while depending on foreign identity systems, foreign control planes, foreign model providers, and infrastructure that cannot easily be replaced.

That is location sovereignty.

It is not necessarily operational sovereignty.

For autonomous systems, sovereignty needs another property:

**The ability to verify, limit, delegate, revoke, audit, and replace every participant in the system.**

That is the direction Genesis Mesh is moving toward.

**The PoC was the beginning**

Looking back at the Intelligent Agents Network PoC is interesting because the basic direction was already there.

Modular agents.

Agent-to-agent communication.

External systems.

Multiple interfaces.

Automation.

Security boundaries.

The missing layer was a portable trust model between those components.

That is what Genesis Mesh became.

The original question was:

**Can intelligent agents work together?**

The question today is much more important:

**Can autonomous systems controlled by different organizations work together without requiring any of those organizations to surrender authority to the others?**

That is the problem I want Genesis Mesh to solve.

And in a world moving quickly toward autonomous infrastructure, sovereign AI, and machine-to-machine economic activity, I believe that question will matter far more than which model happens to be the most powerful.
